# 看盘工作台改造与 TDD 计划

日期：2026-10-20

依据：当前工作区源码评审与本地模拟结果。已有未提交的模型配置、采集修复和打包修复是本次工作的基线。

## 目标与交付顺序

围绕“选择场景 → 检查数据 → 更新必要模块 → 分析 → 查看证据与历史”组织操作。

本轮交付第一阶段：场景一致性、数据质量与时间、独立分析历史、结果优先的页面布局。同步修正与流程直接相关的模型保存语义。第二阶段包含流式正文与任务恢复、盘前假设验证链；第三阶段包含提示词工程和质量评测，不以本轮完成替代这些后续事项。

## 第一阶段范围

### 1. 统一场景

- 显式选择盘前、盘中、盘后、自定义场景；切换场景不触发采集或付费请求。
- 场景给出默认模块集合，普通解析、重新解析、提示词生成使用当前场景。
- 用户可调整数据范围；分析范围和模板名称在提交前可见。
- 主操作为“分析已有数据”或“抓取并分析”；独立“更新数据”只采集数据。
- 历史日期可分析归档，不能发起不支持的历史实时采集。
- 获取模型列表和测试不保存配置；分析使用当前选择但不隐式保存默认模型或密钥。

### 2. 数据质量与时间

- `/api/state` 返回各模块的数据日期、采集时间、记录数（可识别时）、质量状态和说明。
- 状态至少包含缺失、空数据、日期不符、待更新、时间未知、可用；保留本轮采集失败状态。
- 空文件、无有效正文、明显错误日期和本轮采集失败的模块不能静默进入分析。
- 当日动态模块按采集时间提示待更新；盘前固定资料、历史归档不套用实时过期规则。
- 时间未知的旧版归档允许兼容读取，但明确提示无法校验时效。
- 历史日期不以机器当前时间伪装为数据时间。
- 提示词、结果元数据和导出标题使用同一分析时间；保留盘前 09:25、盘后 15:00 的场景标题，单独列出数据采集时间范围和生成时间。
- 页面首次打开即展示已有模块，与已有数据计数一致。

初始时效规则：当日、交易时段内的动态数据采集超过 15 分钟标记待更新。该阈值是产品规则，不代表源站承诺；午间与收盘后应结合最近应更新时点计算，避免休市期间无意义过期。源站没有提供截止时间时，不将采集时间称为行情截止时间。

### 3. 分析历史

- 每次成功分析生成唯一记录，不覆盖同一天同模块的旧记录。
- 记录包含场景、模型、生成时间、模块集合、输入摘要及哈希、提示词哈希和版本标识、正文、耗时。
- 历史记录不包含密钥。保存实际使用的提示词，方便复现。
- 可按日期列出和读取记录；兼容旧 `kimi-analysis-*.md` 文件，不迁移或修改旧文件。
- 使用独立文件原子保存，读取参数做严格校验。
- 页面可以打开本日历史、查看上一次结果，并恢复结果所对应的日期、场景、模块及导出时间。

### 4. 页面布局

- 顶部：日期、场景、当前模型、设置入口。
- 操作条：一个主按钮、更新数据、更多操作；低频操作折叠。
- 主工作区：结论优先，模块状态作为窄辅助栏；小屏时结果在前。
- 模型设置、提示词、运行日志默认折叠；原始数据按模块展开。
- 单项更新放在对应模块行内，不再常驻十个补抓按钮。
- 标签使用原生按钮和 `aria-pressed`，支持键盘操作。
- 清理隐藏的旧版页面结构，修复侧栏指标样式覆盖。
- 任务执行期间锁定会改变任务上下文的控件；使用非全屏进度区，允许继续阅读。
- 不增加前端框架，不改变采集源和采集字段。

## 后续阶段

### 第二阶段：分析过程与连续复盘

- 正文流式展示、查询失败恢复、页面刷新后恢复任务。
- 后台取消与子进程生命周期管理。
- 盘前预期以带证据的假设保存；盘中和盘后逐项验证；不存在前序记录时明确提示。
- 历史结果对比，标注变化而非将前次模型判断视为事实。

### 第三阶段：提示词工程

- 共用规则与场景规则分别维护，避免文档与 Python 硬编码脱节。
- 系统规则与数据输入分离；数据不具备指令权限。
- 简报与完整报告模式、精简词典、允许角色缺席。
- 保留原始证据定位信息，按数据含义压缩而非截断字符串。
- 结构化关键结论、输出校验和固定样例评测。
- 不用自动增加真实模型调用的方式重试或评测；真实调用另按明确授权执行。

## TDD 验收清单

遵循红灯 → 最小实现 → 绿灯 → 必要重构。失败日志和通过日志保存在 `output/workspace-tdd-2026-10-20/`。

### 数据与历史测试

- 空数据不能通过提示词和分析入口。
- 错误数据日期被识别；旧归档时间未知可读但带说明。
- 当日动态数据过期可见；历史数据、竞价资料和非交易时段正确处理。
- 抓取失败保留旧文件，同时阻止它被当作本轮成功资料。
- 同日同模块连续分析得到两份独立记录。
- 历史可列出、读取，旧 Markdown 兼容；非法标识不能访问任意文件。
- 记录没有密钥，输入和提示词哈希对应实际发送内容。
- 历史记录保存失败不能报告成功。

### 页面流程测试

- 切换场景不产生请求；盘前执行后普通重试仍使用盘前模板。
- 首次加载归档即展示数据状态。
- 主按钮根据当前场景的数据状态切换，历史日期禁止无效采集。
- 手工选择模型后分析不会调用保存配置接口。
- 历史结果可重新打开，导出时间不会变成点击复制时刻。
- 任务期间上下文锁定，阅读区不被全屏遮挡。
- 使用真实页面脚本和本地模拟 API 验证流程，所有外部网络禁用。

### 回归与视觉验收

- 运行既有 Python 回归测试、新增行为测试及完整页面 DOM 流程。
- 保留已有模型列表、模型测试、密钥保护、错误提示、采集和打包相关测试。
- 在允许的浏览器工具可用时验收 1366、1575、1920 和手机宽度；DOM 测试不冒充像素级视觉验收。
- 当前应用页面的浏览器访问曾被工具策略拒绝，本轮不改换端口或工具绕过。视觉验收若仍不可用，明确记录未完成。

## 操作边界

- 修改限于看盘服务、页面、相关测试与文档。
- 不改写现有行情归档和用户配置，不调用真实模型接口。
- 不提交、不推送、不重新打包；这些操作不属于本轮交付。
- 本地测试使用临时数据和模拟上游，避免影响运行中的实例。

## 第一阶段交付记录

### 实现位置

- `kanpan-tool/server.py`：数据质量与时间校验、单次输入快照、独立历史记录、历史查询 API、样式资源路由。
- `kanpan-tool/index.html`：场景选择、必要模块更新、失败项重试、显式保存模型、历史恢复、请求乱序保护及任务期间的控件锁定。
- `kanpan-tool/workspace.css`：结果优先的双栏布局、小屏单栏、辅助信息折叠、模块与历史样式。没有增加运行时前端框架。
- `tests/test_workspace_flow.py`：18 项新增后端行为和 HTTP 集成测试。
- `tests/workspace-dom.cjs`：18 项真实页面脚本的离线 DOM 流程测试；请求全部模拟，并禁止 XHR/WebSocket。
- `tests/run_regressions.py`：隔离测试目录，禁止 Python 测试连接非本机地址。
- `tests/test_kanpan_regressions.py`：保留既有回归断言，补齐页面状态依赖的测试桩；将已移除的隐式保存调用检查改为保存后的掩码检查，隐式保存禁用由完整 DOM 流程验证。

页面日常流程为：选日期和场景 → 查看可用资料数量 → 主按钮分析；缺失或过期时先更新必要模块。需要单独采集时使用“更新数据”；失败后“重试失败项”只更新失败模块，不自动重发模型请求。打开历史记录会恢复场景和模块范围，展示历史模型，但保留当前模型选择供下一次分析使用。

- 第一阶段交付时尚未执行真实浏览器多尺寸检查；2026-10-21 已补充完成，并修复手机菜单越界。完整结果见《充分测试报告-2026-10-21.md》。
