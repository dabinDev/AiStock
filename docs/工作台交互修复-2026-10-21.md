# 工作台交互修复与 TDD 验收

## 依据与边界

用户明确认可右侧资料卡片与展开查看，要求修复模型输入、按钮排布、配色、AI 看盘流程和分析范围。以旧版深色底、橙色主操作、青绿状态色为视觉依据，保留已有的资料原文、分析历史、复制和任务恢复。

本轮只调整 `kanpan-tool/index.html`、`kanpan-tool/workspace.css` 与相关测试。保持采集源、行情字段、模型接口及既有提示词模板不变。不改本机密钥、历史数据；不进行真实上游请求、打包或 Git 提交。

## 已确认的问题

1. 已保存密钥的掩码写入密码框，用户容易把新密钥追加到掩码后；清空后刷新又填回。
2. 模型只有下拉框，没有手动输入入口；获取列表之前无法输入新模型 ID。
3. 分析范围藏在更多操作中；增加模块会自动切换成自定义模板，改变用户的分析意图。
4. 主要操作、场景、范围分散，按钮层级不清；缺数据或历史日期被禁用时缺少明确的下一步。
5. 新版青蓝色主按钮和卡片色与旧版视觉偏好不一致。

## 修复方案

- 模型配置：密钥输入默认空白，已保存状态独立显示；留空沿用已有密钥，刷新不覆盖未保存输入，保存成功清空输入。模型支持直接填写 ID 和从已获取列表选择；列表、测试、保存各有明确语义与反馈。
- AI 看盘：盘前、盘中、盘后、自定义使用可直接点击的场景按钮。先选场景，再查看/调整资料，再开始分析。切换场景不发起分析。
- 分析范围始终可见；默认延续盘前 2 项、盘中 4 项、盘后 10 项。调整范围保留场景模板，明确标记“已调整”；提供恢复推荐、仅选当前可用、清空入口。仅选可用是显式缩小范围，不自动忽略缺失资料。
- 主按钮固定为“开始分析”，旁边说明将直接分析或先更新哪些资料；“更新资料”是次操作，不调用模型。历史归档无法补抓时说明原因及处理办法。
- 增加可选的本次关注点，追加到当前场景生成的完整提示词，保留系统规则、日期和所选资料；随实际提示词进入历史记录。更换日期清空关注点，避免跨日误带。
- 深黑灰面板、橙色主操作和选中状态；青绿用于数据可用，警告色用于需更新。减少无意义大色块，统一按钮高度、分组、间距与窄屏换行。
- 右侧资料卡片、原文展开和分析历史保留，刷新时尽量保持用户打开的原文。

## TDD 顺序与验收

先添加 DOM 行为测试并记录失败，再实施最小修复，最后运行全量 Python/DOM 与真实浏览器布局验证。

- 密钥不回填掩码；输入、刷新、清空、保存成功与保存失败路径正确。
- 手填模型、选择列表、获取失败后保留选择、测试不保存、显式保存默认。
- 场景切换不请求；范围可见，增删范围不改模板，推荐与仅选可用行为正确。
- 关注点追加完整提示词、请求失败不发起模型分析、日期切换清空。
- 任务执行时冻结场景/范围/关注点/配置；重复点击不重复提交。
- 历史日期、无资料、采集部分失败、任务查询恢复继续通过。
- 卡片原文展开、历史读取、复制功能继续可用。
- 真实浏览器检查宽屏、平板、手机宽度，无横向溢出、遮挡或截断。
- 全程比较 `data/` 和 `.local-config/` 的 SHA-256，确认真实数据与配置不变。

测试证据目录：`output/workspace-fix-2026-10-21/`。

## 实施与验证结果

- 配色经用户确认：恢复深黑底、灰黑卡片、橙色重点和少量青绿色状态提示。
- 模型 ID 使用可编辑输入框，已获取的模型使用独立原生下拉框完整展示，避免输入候选列表按照当前 ID 过滤后看不到其他模型。
- 密钥掩码仅作为保存状态显示，不写入输入框；输入框保留密码遮挡。保存成功清空新密钥，保存失败保留输入并解锁。
- 设置默认收起，由右上角“模型设置”展开；不再重复占用一整条关闭状态栏。获取列表紧邻模型输入，测试与保存排列在设置底部。
- 保持原生 HTML/CSS/JavaScript，不新增前端依赖；模型选择与手动输入复用同一选定值，资料范围操作复用既有更新逻辑，避免并行维护多套状态。
