## TDD 与修复记录

本轮先重新运行 108 项 Python、18 项 DOM 基线，全部通过，再补充异常测试。证据保存在 `output/workspace-deep-2026-10-21/`。

1. **分析字段类型错误可能令后台任务无法结束。**
   `model` 为数字、列表等类型时，接口以前会创建任务，随后工作线程可能在异常保护外退出。现在入口拒绝非字符串字段，直接调用工作线程时也能结束为失败。对应 `test_invalid_analysis_fields_are_rejected_before_creating_job`、`test_invalid_model_in_direct_worker_ends_in_failure_without_upstream`。
2. **单个资料文件无法读取会打断整个状态接口。**
   现在对 UTF-8 解码失败和文件读取错误逐项容错，标为“读取失败”；其余资料仍可正常显示，该项不能用于分析。对应 `test_unreadable_module_does_not_break_other_data_and_blocks_analysis`。
3. **明确填写但格式错误的采集时间被当成旧版缺少时间。**
   现在解析完整时间行，拒绝空值、仅日期、非法文本和合法时间后追加的脏内容；真正没有时间字段的旧资料继续兼容。对应 `test_explicit_malformed_time_is_not_treated_as_missing_legacy_time`。
4. **损坏的历史索引可能使历史列表无法读取。**
   对日期、正文、目标列表、时间和上下文类型进行检查。损坏记录被跳过，有效记录仍可打开。对应 `test_corrupt_history_metadata_is_skipped_without_hiding_good_records`。
5. **分析完成后状态刷新失败会隐藏成功结论。**
   现在先展示已返回的结论，再刷新资料状态；刷新失败单独提示，保留结果和任务日志。对应 DOM 用例“任务已完成但状态刷新失败仍展示成功结论”。
6. **任务查询失败丢失跟踪，用户可能重复提交分析。**
   只对原任务的 GET 状态查询进行有限重查。连续 3 次失败后保留任务标识，锁定重复提交并提供“恢复任务查询”。恢复操作不会重新发送抓取或分析请求；若服务明确返回任务不存在，则提示先检查历史并解锁。恢复采集查询后不会自动发起模型调用。覆盖瞬时断线、持续断线、重复恢复、采集部分失败和服务重启。
7. **Markdown 链接缺少协议检查。**
   仅将 HTTP/HTTPS 地址生成可点击链接，并转义 HTML 属性引号。覆盖 `javascript:`、`data:`、编码协议、属性注入和原始资料中的 HTML 文本。
8. **采集进程退出码为 0，但输出损坏时仍显示完成。**
   现在在采集成功前核验文件可读性和资料质量；无效输出归为失败，不计入成功数量。对应 `test_fetch_zero_exit_with_unreadable_output_is_failure`。
9. **375 像素宽度下“更多操作”菜单左侧越界。**
   实机复现时菜单左边界为约 -3.70 CSS 像素。移动端改为相对操作栏定位，修复后左边界 16、右边界 344，位于 360 CSS 像素的内容视口内；390 和桌面宽度也通过。

## 实现原则

- **KISS / YAGNI：** 保持现有 Python 服务和原生页面；查询恢复仅针对当前页面内的任务，没有扩展为持久化调度系统。
- **DRY：** 复用 `data_quality` 校验采集输出；采集失败目标的终态处理集中在任务查询完成处，正常查询和恢复查询共享处理逻辑。
- **单一职责：** 输入校验、资料读取容错、历史索引校验和页面状态恢复分别在对应边界处理，避免单项损坏影响整个工作台。
